# Authenticated-page rebuild — architecture

## Chosen direction: **The Editorial Worktable**

STUDIO’s authenticated workspace will behave like a paced worktable, not a SaaS dashboard. The desktop structure is a dark utility spine at the far left, an uninterrupted warm-paper production field, and—only where required—a charcoal editing field. Navigation provides orientation; it must not compete with the work. The public landing stays unchanged.

| Surface | Composition | Data and actions retained |
|---|---|---|
| Overview | A low, dense operational ledger followed by a wide horizontal hand-off strip and one acid-lime next move. No duplicate route banner or generic search header. | Live product/post counts, refresh, live source and post links, readiness state, Brand status. |
| Products / Brand | A contact-sheet catalog spanning the primary field; a narrow black Brand ledger hugs its right edge; the upload form appears as a deliberate second act below. | Live product list/delete, create/upload, test catalog, saved Brand fetch, Brand navigation. |
| Brand | A full-height editing desk: raw Brand fields form the quiet left work area and the saved expression/placement preview occupies a black right sheet. | Existing Brand API, logo upload, color/font/tone inputs, save state. |
| Studio | One large control-room frame from header to export: source and direction rail, gridded stage, finishing and caption rail. The page does not inherit the generic workspace topbar/search row. | Existing compose/import, product selection, controls, local render, configured/neutral Brand, captions, approval, export, delivery. |

## Shared rules

The serif display type appears only once per route, at the start of the working field. Monospace labels describe state and sequence. Button appearance is intentionally binary: an acid-lime action commits the next step, while subdued paper or charcoal controls change local context. Cards are not default containers; borders, negative space, rails, and edge alignment establish hierarchy.

Each main surface must have exactly one primary action. Data-unavailable notices sit in the document flow, use the same dimensional logic as source records, and must never replace the rest of the workspace. On mobile, the navigation becomes an intentionally constrained tool strip, then the worktable continues vertically without a horizontal escape hatch.
